# HexTravel Admin

Русскоязычная админ-панель HexTravel для создания, редактирования и публикации
туров через REST Gateway. Стек проекта — React, TypeScript в режиме `strict`,
React Router, `liquid-glass-react` и esbuild.

## Источники требований

- Сценарии и критерии приёмки описаны в [ТЗ](HexTravel-Admin-Spec.md).
- Маршруты, схемы и доступные операции определяет [OpenAPI](api-docs.json).
  При расхождении сверяй конкретную операцию с DTO и контроллером Gateway,
  если backend доступен. Подтверждённые расхождения записывай в [README](README.md).
- Для запуска и настройки стенда используй команды и параметры из README.

## Работа с кодом

- Точка входа находится в `src/main.tsx`, маршруты и навигация — в `src/App.tsx`.
  Сборка, локальный сервер и прокси реализованы в `scripts/site.mjs`.
- Авторизация и HTTP-ошибки обрабатываются в `src/api/client.ts`. Новые операции
  с каталогом добавляй в `src/api/catalog.ts`, типы API — в `src/api/schema.ts`.
- Формы и разделы тура находятся в `src/editor/`. Переиспользуй компоненты
  `src/components/`, существующие правила валидации и стили из `src/styles.css`.
- Ограничивай правки рамками задачи. Используй `import type` для импортов типов.
  При изменении зависимостей обновляй `package-lock.json` вместе с `package.json`.
- Публичные параметры стенда описывай в `.env.example`. Храни локальные
  настройки в `.env`, пароли и токены исключай из сборки и журналов.

## Сценарии и данные

- Вход в панель доступен роли `ADMIN`. Проверку полномочий выполняет Gateway.
  Храни токены в памяти вкладки. Используй общий refresh для параллельных
  ответов `401` и повторяй исходный запрос один раз.
- Создавай тур с `isPublic: false` и открывай редактор по полученному `id`.
  Передавай в `PATCH` изменённые поля. Публикуй отдельным запросом с
  `isPublic: true`. Опускай пропущенные поля и сохраняй введённые `0` и `false`.
- Сценарий публикации допускает пропуск программы, транспорта, бронирований
  и галереи. Для сохранённых связанных записей используй операции из OpenAPI.
- Показывай предупреждение об уходе с несохранёнными правками. После запроса
  с неопределённым исходом сверяй данные на сервере перед повторной записью.
- Сохраняй точность `int64` для OSM ID и используй UUID места для привязок.
  При повторе загрузки фото используй `photoId` уже созданной записи.

## Интерфейс

- Пиши пользовательские тексты на русском. Используй Apple HIG как основу
  для системной типографики, отступов, скруглений и анимаций HexTravel.
- Адаптируй навигацию под устройство. На десктопе она боковая, на планшете
  верхняя, на телефоне нижняя. Для навигации и тулбаров используй `GlassSurface`,
  для формы и списка — читаемые однотонные поверхности.
- Для изменённых элементов проверяй светлую и тёмную темы, клавиатуру
  и видимый фокус. Учитывай `prefers-reduced-motion` и
  `prefers-reduced-transparency` для анимаций и стеклянных поверхностей.

## Проверки и коммиты

- Используй Node.js 22 или новее. Установи зависимости через `npm ci`,
  когда их нет в рабочей копии. Для локального запуска используй `npm run dev`.
- Для проверки кода запускай `npm run build`. Эта команда включает
  `npm run typecheck` и собирает статические файлы в `dist/`.
- Для правок UI проверь затронутый сценарий в браузере. Для правок API
  используй тестовые данные и сверяй результат с контрактом. В отчёте
  укажи выполненные проверки и ограничения среды.
- Пиши заголовки коммитов на английском в формате Conventional Commits.
  Пример заголовка — `feat(admin): add tour management panel`.
  Тело коммита пиши на русском и сохраняй технические термины.
