# HexTravel Admin

Русскоязычная веб-панель для администраторов HexTravel. В разделе «Цифровизация туров» можно сохранить черновик в глобальном каталоге, добавить точки и связанные записи, а затем опубликовать тур. Повторное открытие карточки загружает сохранённые данные из Gateway.

[Техническое задание](HexTravel-Admin-Spec.md) · [Контракт OpenAPI](api-docs.json)

## Локальный запуск

Нужны Node.js 22 или новее, npm и запущенный HexTravel REST Gateway.

```bash
npm ci
cp .env.example .env
npm run dev
```

Панель доступна по адресу [http://127.0.0.1:5173](http://127.0.0.1:5173). Пример конфигурации направляет запросы `/api/v1` в локальный Nginx по HTTPS. При локальном сертификате, выпущенном через `make certs` в backend-репозитории, передайте его путь Node.js.

```bash
NODE_EXTRA_CA_CERTS=/path/to/cert/cert.pem npm run dev
```

Используйте существующую учётную запись с ролью `ADMIN`. Токены хранятся в памяти вкладки. После перезагрузки войдите снова и откройте сохранённый тур из каталога.

## Конфигурация и сборка

| Переменная | Назначение |
| --- | --- |
| `HEXTRAVEL_API_BASE_URL` | Базовый URL вместе с префиксом API. Значение по умолчанию — `/api/v1` на origin панели. Для отдельного Gateway укажите полный HTTPS URL с `/api/v1` и разрешите origin панели, методы и заголовки `Authorization` и `Content-Type` в CORS. |
| `HEXTRAVEL_DEV_PROXY_TARGET` | Origin Gateway для локальной разработки с относительным URL API, например `https://localhost`. |
| `HEXTRAVEL_PHOTO_FILE_LIMIT_MIB` | Лимит файла в МиБ. По умолчанию 20. |
| `HEXTRAVEL_PHOTO_REQUEST_LIMIT_MIB` | Лимит multipart-запроса в МиБ. По умолчанию 10. При проверке панель резервирует 1 КиБ и длину имени файла под служебные данные multipart. Значение `0` отключает эту проверку локально. |

```bash
npm run typecheck
npm run build
```

Сборка использует esbuild и создаёт статические файлы в `dist/`. Публичные параметры API и загрузки встраиваются при сборке. Для нового стенда установите значения в `.env` и пересоберите приложение. Разместить панель можно в корне сайта или в подкаталоге, например `/admin/`. Адрес открытого редактора содержит фрагмент `#/trips/<tripId>`.

## Поведение API

| Endpoint | Фактическое поведение и использование в панели |
| --- | --- |
| `GET /api/v1/me/photos/trip/{tripId}` | Swagger указывает одиночный `PhotoResponse`. Контроллер возвращает `List<PhotoResponse>`. Галерея читает массив. |
| `POST /api/v1/me/photos/{photoId}/file` | Swagger описывает multipart бинарной схемой. Gateway ожидает часть `file` и возвращает текст `Saved`. |
| `GET /api/v1/me/photos/{photoId}/file` | Gateway возвращает байты как `application/octet-stream`. Панель загружает их с Bearer-токеном и использует расширение из метаданных для превью и скачивания. Ответ `404` переводит фото в состояние «Файл не загружен». |
| `GET /api/v1/trips/{tripId}/transports/{transportId}/flight` | Ответ `404` при отсутствии рейса открывает возможность его добавить. |
| `POST /api/v1/trips/{tripId}/bookings` | `confirmationNumber` в запросе — телефон клиента. Пример в схеме ответа содержит буквенно-цифровой номер, поэтому форму проверяет DTO запроса с правилом `^\+?[0-9]{10,15}$`. |
| `POST /api/v1/places` | `osmId` передаётся целым JSON-числом с точностью `int64`. При `409` панель ищет существующее место по этому ID. `osmTags` передаётся строкой с JSON-объектом. |
| `POST /api/v1/trips`, `PATCH /api/v1/trips/{tripId}` | Создание передаёт `isPublic: false`. Сохранение карточки отправляет изменённые значения. Публикация отправляет отдельный `PATCH` с `isPublic: true`. |

Приложение учитывает ограничения DTO, включая будущие даты, диапазоны координат и минимальные длительности. Для `date-time` используется часовой пояс браузера и смещение конкретной даты. Время событий отправляется как `HH:mm:ss`. После сбоя с неопределённым результатом записи панель предлагает сверить данные на сервере, прежде чем повторять действие.

## Проверка

| Проверка | Результат |
| --- | --- |
| REST-клиент на заглушке контрактных ответов | Проверены отказ для `USER`, вход `ADMIN`, единый refresh для параллельных `401`, выход во время refresh, черновик, сохранение, публикация и запросы всех разделов. |
| Граница `int64` и галерея | Проверены точное значение `9223372036854775807`, выбор UUID места, multipart с частью `file`, повтор загрузки к существующему `photoId`, чтение Blob, `204`, `409`, `413`, `428` и сетевой сбой. |
| Строгая типизация и сборка | `npm run build` прошёл с установленными зависимостями. Созданы `dist/app.js` и `dist/app.css`. |
| Dev-сервер | В режиме `--dev` проверены пересборка, выдача HTML, JS, CSS и source maps, передача запросов к Gateway и ответ `502` при сбое прокси. HTTP-обработчики проверены с заглушкой сетевого слоя. |
| Браузерная приёмка | Среда проверки отклоняет открытие локального порта с `listen EPERM`. Проход сценария в Safari и Chromium с живым Gateway остаётся открытым. |
